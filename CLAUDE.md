# CLAUDE.md

One static page: a contact card over a WebGL sky, plus a plain 404, and a Worker for `/mcp`.

## Tech Stack

- **Framework:** Next.js 16 App Router, `output: "export"`, prerendered to `dist/`. Routes: `/` (`src/app/page.tsx`), 404 (`src/app/not-found.tsx` → `dist/404.html`, `noindex`), `/sitemap.xml` (with image entries), `/robots.txt`, `/manifest.webmanifest` (`src/app/manifest.ts`), `/llms.txt` (`src/app/llms.txt/route.ts`), `/cv.json` (`src/app/cv.json/route.ts`), `/resume.pdf` (`src/app/resume.pdf/route.ts`). All of them are built from `personal.ts`, `products.ts`, `i18n.ts`, the build-time repo list and the CV feed; never add a second page.
- **Dev:** `devIndicators: false` in `next.config.ts`, so `next dev` shows no Next.js badge.
- **UI:** Tailwind v4 (`@theme inline` + `@utility`, via `@tailwindcss/postcss`). Server components by default; `"use client"` only for the sky (`space-background.tsx`), the clouds (`clouds-canvas.tsx` → `src/lib/clouds.ts`, one three.js full-screen shader, imported after `load`, skipped on Save-Data), cursor glow, the PDF button, the portrait dialog, the planets (`repo-planets-canvas.tsx` → `src/lib/repo-planets.ts`, one canvas that draws the repo planets and the logo planets from `src/lib/logo-planet.ts` and `src/lib/logo-motion.ts`), the pause button (`motion-toggle.tsx`), the privacy OK button (`privacy-ack.tsx`), the Vienna globe launcher (`city-globe-launcher.tsx`, which imports `city-globe-stage.tsx` → `src/lib/city-globe.ts` only on click) and `effects-init.tsx`.
- **Globe data:** `src/lib/globe-data.ts` (coastlines, Austria, borders) is generated by `scripts/generate-globe-data.ts` from Natural Earth through `world-atlas`: run `pnpm add -D world-atlas`, `node scripts/generate-globe-data.ts`, then `pnpm remove world-atlas`. It is loaded only after a click on "Show on the globe". Nothing is fetched at run time.
- **Fonts:** self-hosted woff2 in `public/fonts/` with versioned names (Inter Variable latin, Geist Mono 400/500 latin, Parkinsans weight 300 to 800 for the name only, plus small `*-extra-*` files for ć č đ š ž, cut with fonttools' `pyftsubset` from `~/powertools/py/bin` and woff2 output). The profile header SVG embeds Inter and Parkinsans. `@font-face` sits at the top of `globals.css`. Do not preload them: it pushed LCP from 0.9 s to 1.5 s on slow 4G. To change a font, ship a new file name (the `/fonts/*` cache rule is immutable).
- **Icons:** `<Icon>` (`src/components/icon.tsx`) renders inline SVG from `src/lib/icon-data.ts`. Sets in use: `circle-flags`, `lucide`, `simple-icons`. A new `set:name` needs `pnpm icons` (run `pnpm add -D @iconify-json/<set>` for each set first, then remove them again).
- **GitHub data:** `src/lib/github.ts` runs at build time. `getRepos` picks the repos and adds every language at 3% or more with its GitHub Linguist color (one GraphQL `repository.languages` query per repo; colors are validated as `#rrggbb` and dropped otherwise). `getContact` reads the public email and the LinkedIn social account from the GitHub profile; `personal.ts` holds neither. `GITHUB_TOKEN` is **required**: GitHub shows a profile email only to authenticated requests. Set it as a Cloudflare build variable. Locally, when it is unset, `github.ts` asks `gh auth token` at run time, so `pnpm dev`, `pnpm build` and the pre-commit hook work without a token file (nothing is written to disk; Next caches the answers with `force-cache`). Any non-200 answer, a missing email or a missing LinkedIn fails the build on purpose. `getProject(login, repo)` (built for project pages, no page uses it yet) returns the default branch, the README rendered by GitHub's `/markdown` endpoint (GFM, repo context) and the last published releases (`per_page=5`, drafts and prereleases dropped, assets kept). `src/lib/readme-html.ts` (`sanitizeReadme`, `sanitize-html`) cleans that HTML: resolves relative links (GitHub blob URLs) and images (raw.githubusercontent.com) against the repo and branch, rejects `..` paths, keeps only http(s) and mailto, opens web links with `noopener noreferrer`, keeps images only from GitHub image hosts, drops badges (shields.io, badge.fury.io), the first `h1`, landmark tags, non-checkbox inputs and links left empty, and keeps links around nested images. Both are covered only by tests so far.
- **CV feed:** `scripts/cv-fetch.ts` runs before `next build` (`pnpm build`, `pnpm dev` and `pnpm check` all start with it; `pnpm dev` fetches once at start) and asks the jobsearch app (hirista) for `GET {CV_FEED_URL}/api/public/cv` with `Authorization: Bearer {CV_FEED_TOKEN}`, a 20 s timeout and `redirect: "error"`. `CV_FEED_URL` is the origin `https://hirista.app`, never the old `js.stevanpavlovic.com` (its 308 would drop the bearer); a URL that is not https fails before any request, except `http:` on `127.0.0.1`, `localhost` and `[::1]` for tests. The script writes the parsed résumé, with `basics.phone` blanked (`stripPrivate`), to the gitignored `.cv/cv.json` and the source (`feed` or `live`) to `.cv/source`; `getCv()` in `src/lib/cv.ts` only reads that file (once per process), so every page, route and the PDF show one version. **Fallback:** only a 20 s timeout, a network error or a 5xx makes the script use the live `https://stevanpavlovic.com/cv.json` (source `live`, a warning in the log). A 404 (the feed answers 404 with an empty body to every refusal: no or wrong token, wrong method, no résumé saved), any other non-200, a redirect, a missing or non-https variable, bad JSON or a schema failure fails the build and never falls back. **Guard:** `scripts/cv-guard.ts` runs after `next build` and fails the build when the feed's `updatedAt` is newer than the built data (a résumé saved during the build; a newer build is on its way). It is skipped after a `live` fallback or when the feed does not answer. Both scripts load `.env.local` when it exists; `process.env` wins. `cvSchema` mirrors jobsearch's `resumeDataSchema` (`src/cvexp/types.ts` there): `basics`, `summary`, `experience`, `education`, `skills`, `languages`, `projects` (http(s) links only), every field defaulted, plus `updatedAt` (ISO); there is no `cvexp` dependency, as the npm package lacks `projects`. `src/lib/cv-feed.fixture.json` is a byte copy of hirista's `fixtures/cv-feed.json` and `src/lib/cv-contract.test.ts` parses it with `cvSchema`; `.prettierignore` keeps it byte-exact. Change a feed shape in both repos in the same session. Both variables are **required**: Cloudflare build variables, GitHub Actions secrets (`ci.yml`) and Dependabot secrets, locally `~/work/website/.env.local` (gitignored, holds `CV_FEED_URL` and `CV_FEED_TOKEN`). Never print the token; no error message holds it or the URL. Saving a résumé in hirista fires this site's Workers Builds deploy hook. The integration contract and the secrets matrix live in the hirista repo's `DEPLOYMENT.md`, section "Integration contract: hirista.app ⇄ stevanpavlovic.com" (a private repo, so no link). `src/app/cv.json/route.ts` serves the result as `/cv.json`; `src/lib/cv-llms.ts` adds Experience, Skills, Education and, when there are any, the résumé's projects to `llms.txt`.
- **Static files:** there is no committed PDF. `/resume.pdf` is a `force-static` route: `src/lib/resume-file.ts` renders the feed's résumé once per build with `@react-pdf/renderer` (`src/lib/resume-pdf.ts`, a port of cvexp's layout; Inter from `@fontsource/inter`; colors in `theme.ts`) and reads the photo from `public/` when `basics.pictureUrl` is on the site's own origin (`public/stevan-pavlovic.jpeg` backs the feed's `pictureUrl`). The button downloads it as `Stevan_Pavlovic_Resume.pdf`. Portraits (`public/portraits/`), favicons and `og-image.jpg` (1200x630: the sky, the portrait, name, title, Vienna) are committed. No file in `public/` is generated at build time; `src/lib/resume-facts.ts` only reads the page count (page tree `/Count`, also inside Flate object streams, else `/Type /Page` objects) and the size in KB from the generated PDF for the PDF tooltip, and fails the build when it finds no page count. `cv.json` is not committed: it comes from the CV feed at build time (see above).
- **Content:** `src/lib/personal.ts` (name, title, summary, city, website, GitHub); email and LinkedIn come from GitHub (see above); all UI strings in `src/lib/i18n.ts`.
- **Products:** `src/lib/products.ts` is hand-written on purpose (the CV feed's `projects` have no role, logo, color or category, and a résumé edit must not reshape the card): `key`, `name`, `url`, `schemaType` (`WebApplication` for hirista, `SoftwareApplication` for Safety Real Time) and `applicationCategory`, with `role`, `period` and `line` from `en.products.items[key]` and the colors (`disc`, `mark`, `accent`, `tint`) from `productPalette` in `theme.ts`. `src/lib/product-marks.ts` holds the mark path data (`viewBox`, a `transform`, layers with `ink` `mark` or `accent`); the Safety Real Time mark is the six paths of `https://safetyrealtime.com/wp-content/uploads/2022/11/srt_logo.svg`, navy on green after the brand's favicon. They feed the product tiles, the JSON-LD (`WebApplication`/`SoftwareApplication` with the person as `creator`), the `llms.txt` "Products" section (`productLlmsLines`, after the open-source projects; `isProductUrl` drops a résumé project whose host is a product's, so hirista is listed once), the `/mcp` `products` tool and the profile README. Both files use relative `./x.ts` imports, so `node --test` and `src/profile/cli.ts` load them. The tile period is hand-written while the fleet popover reads its own from the feed; if they drift, take the tile's from the feed.
- **Pkg mgr:** pnpm 12 (`packageManager`), Node 24 (`.nvmrc`), both enforced by `engines` with `engineStrict`. All pnpm settings live in `pnpm-workspace.yaml`: the build-script allowlist (`allowBuilds`, `strictDepBuilds`), a one-day `minimumReleaseAge`, `trustPolicy: no-downgrade` with one exact `trustPolicyExclude` entry (`semver@6.3.1`, a 2023 security backport without provenance; evidence in the commit that added it), `blockExoticSubdeps` and `verifyDepsBeforeRun: install` (scripts install first when the lockfile changed). Keep `package.json` scripts to the eight that exist (`build`, `check`, `dev`, `fix`, `icons`, `prepare`, `preview`, `profile:build`). Add a trust exception only as an exact `name@version` with checked evidence, never by turning the policy off.
- **Profile mirror:** `src/profile/` builds the README and images for `pavstev/pavstev` from `personal.ts`, `products.ts`, `i18n.ts`, `icon-data.ts`, `theme.ts` and the same `getRepos` call as the site. The README lists the repos, then a "## 2 products" section (links only, left out when the list is empty; the product links must be https but are never fetched, as external hosts would make `pnpm check` flaky). `render.ts` is pure (data in, `{ path, contents }[]` out, deterministic); `cli.ts` is the only file that reads or writes. Output goes to the gitignored `.profile-out/`. `.github/workflows/profile.yml` pushes it to `pavstev/pavstev` with the deploy key secret `PROFILE_DEPLOY_KEY`. The code never reaches the Next.js bundle (nothing in `src/app` imports it). The header is a generated SVG with Inter embedded; keep it under 120 KB.
- **Worker:** `worker/index.ts` is `main` in `wrangler.jsonc` (`nodejs_compat`). `assets.run_worker_first` is `["/mcp", "/mcp/*"]`, so only those paths reach it; every other path is served straight from `dist`. It routes `/mcp` and `/mcp/*` to `mcp.ts` and passes anything else to `env.ASSETS`. There is no Ask panel and no `/api` route: the owner removed them, with their human check and AI binding, on 2026-10-08; do not add either back without a new decision. Bindings: `MCP_LIMITER` (rate limit, 20 per 60 s, keyed by `CF-Connecting-IP`) and `ASSETS`. `worker-configuration.d.ts` is generated by `CLOUDFLARE_LOAD_DEV_VARS_FROM_DOT_ENV=false pnpm exec wrangler types` (rerun after any binding change; without the variable wrangler copies the names in `.env.local` into the file), committed, and excluded from Prettier, ESLint and the root `tsconfig.json`; `worker/tsconfig.json` extends the root one and includes it. Errors are JSON `{ "error": code }` with `Cache-Control: no-store`. `facts.ts` reads `/cv.json` (zod schema, `projects` included) and `/llms.txt` from `ASSETS`, caches the promise per origin and drops it on failure, and holds the text helpers `/mcp` uses. `wrangler.jsonc` has `workers_dev: false` and `preview_urls: false`: the Worker answers only on the custom domain.
- **`/mcp`:** a stateless MCP server (`@modelcontextprotocol/sdk`, `WebStandardStreamableHTTPServerTransport`, 16 KB body cap), built per request after the rate limit; `POST` only. Six read-only tools without input: `profile`, `experience`, `skills` (from `cv.json`), `projects`, `products` and `contact`. `projects` lists the "Open-source projects" section of `llms.txt`, then the résumé's projects from `cv.json` (so hirista can show up in `projects` and `products`, by choice); `products` is the "Products" section of `llms.txt` ("Not available." when it is missing); `contact` is the "Links" section. ESLint's `import-x/no-unresolved` ignores the SDK's subpath imports in `worker/`.
- **Checks:** `pnpm check` is the one gate: `prettier --check`, ESLint (zero warnings), `tsc` (the strict `tsconfig.json`), `tsc -p worker/tsconfig.json`, the tests (`node --test` over `src/**/*.test.ts` and `worker/**/*.test.ts`), knip (strict `knip.config.ts`), `pnpm build` (CV fetch, `next build` with its own type check off because `tsc` already ran, CV guard) and the profile validation with link checks. It changes no tracked file. `pnpm fix` applies Prettier and ESLint fixes. husky runs `pnpm check` before every commit (`.husky/pre-commit`).
- **CI:** `.github/workflows/ci.yml` runs `pnpm check` on pushes and pull requests and fails when the tree changes. Dependabot opens grouped weekly updates.
- **Deploy:** every push to `main` makes Cloudflare build the repo and publish `dist` as Workers static assets with the Worker in front of `/mcp` (`wrangler.jsonc`, `404.html` for unknown paths). The Workers Builds build command is `pnpm run build` (it carries the CV fetch, `next build` and the CV guard). Build variables: `GITHUB_TOKEN`, `CV_FEED_URL`, `CV_FEED_TOKEN`. The Worker has no secrets. Nobody deploys by hand: do not run `wrangler deploy` or `pnpm deploy`. Push to `main` only when asked and after `pnpm check` passes. `public/_headers`: immutable for `/_next/static/*` and `/fonts/*`, one day plus stale-while-revalidate for `/portraits/*`, the favicons, the manifest icons and `og-image.jpg`; HTML and `resume.pdf` revalidate every time. `/*` carries the security headers and a CSP (`'self'` and Cloudflare Web Analytics; scripts and styles need `'unsafe-inline'` for Next's inline payload and style attributes; `img-src` also allows `data:`, which no CSS mask needs since the Danube wave was removed (tighten it only after testing on the live site), and `serve` ignores `_headers`, so test CSP changes on the live site); every non-HTML rule detaches the CSP and `X-Frame-Options` with `! Header-Name`, so they reach pages only. Keep the rules disjoint (Cloudflare joins duplicate headers with a comma).

## Non-negotiables

- **No comments, JSDoc, TODO/FIXME/XXX/HACK** in source.
- **Run `pnpm check` before declaring done.**
- **No `eslint-disable`**: zero-warning policy.
- **No `any`** → use `unknown` or generics. **No `!`** non-null assertions.
- **No hardcoded hex/hsl** outside `globals.css` or `src/lib/theme.ts`.
- **No inline UI strings** → `src/lib/i18n.ts`.
- **Tailwind v4 paren syntax** (`bg-(--surface)`) over bracket syntax.
- **Never edit generated files** in `dist/`. **Never commit `.env`.** **Never deploy by hand.** **Never edit `pavstev/pavstev` by hand** (the Action overwrites it).

## The card

- Order: portrait (154 px, 134 px on phones and short screens, 128 px below 760 px tall; a WebGL2 glass bead from `src/lib/portrait-bead.ts` follows the mouse, or the finger after a 320 ms press and hold on touch, where a short tap still opens the dialog and a swipe still scrolls; it magnifies the photo with chromatic edges, a glint and a soft caustic, stretches with speed, starts on first use and stops drawing when it is gone; no bead under reduced motion, Save-Data or a software renderer; the orbit speeds up on hover; click opens a dialog where the 800 px image morphs from the circle to the `--radius-lg` corners; the same bead code (`wireBead` in `src/lib/portrait-effects.ts`) runs over the dialog image with a 64 px radius once the morph has finished, the card bead frees its context on open, and the dialog bead frees its own on close, so at most one bead context exists), name, summary (Light 300, faint halo, a round `circle-flags:at` after the city; blur-in, skipped when hydration starts after 1 s so painted text never vanishes), PDF button and three contact links that share one style (dark glass, the repo-card radius `--radius-lg`, a metal ring whose highlight faces the cursor, an iridescent ring, glow and light sweep on hover, one 0.75rem gap; all four get the proximity zoom from `src/lib/cursor.ts` (`[data-proximity]` on the actions row; distance is measured to the button's core segment and the scale is capped so a button never grows past half the gap); the PDF button keeps its aurora and click ring sequence; every button has a tooltip placed by `src/lib/contact-links.ts`, which weighs covering a button over covering text; the PDF tooltip (`resume-tip.tsx`) is a glass sheet that feeds out of the button edge like a printed page, with a small paper page whose skeleton lines draw in, and the page count and size read from the generated PDF at build time by `src/lib/resume-facts.ts`), the strips (`card-strips.tsx`, layout E below): the repo strip (heading "N open source projects" from an i18n template; each row is a card with a stretched link: a three.js planet, the name, then one chip row with the languages first (tinted with their GitHub colors) and the topics after (GitHub's topic blue, `--github-accent` on `--github-accent-muted`, from Primer's dark tokens), fitted to the width by `src/lib/repo-tags-fit.ts` with a "+N" button that opens a popover listing all of them; the planets are one shared canvas at about 30 fps with dark night sides, two-tone lit sides, drifting cloud swirls, a breathing rim, rings, bands, a moon or craters, and they spin up on hover; the CSS planets stay as the fallback; descriptions drop from two lines to one below 1000 px tall and rows tighten below 823 px), then the products column, `© year name` under a faint gradient divider, no halo.
- Name: set in Parkinsans. The visible letters are `aria-hidden` spans (`--i` index) next to an `sr-only` copy, so screen readers read the name once. A pure-CSS 5.6 s "signal tuning" intro (blur, scan lines, rose and teal slices, neon flicker) starts at first paint and stays readable after about 1 s. `src/lib/name-glitch.ts` then sets `data-glitch` for a 1.9 s burst every 8 s, rests after 30 s without input and resumes on input; it sets `data-tuned` first so the intro never replays. Each burst is a WebGL tear (`src/lib/name-tear.ts`, raw WebGL2 created on the first burst: the letters redrawn into a texture, torn horizontal bands, RGB split, scan lines, 0.52 s, `data-tearing` hides the DOM letters meanwhile) followed by an axis-morph wave (each letter swings weight 700 to 300 to 800 and squeezes and stretches with `scaleX`, staggered 32 ms). Reduced motion, forced colors, software renderers and a held or paused scene skip the tear. Keep every flicker under three flashes per second.
- Layout E: `.card-strips[data-strips]` (`card-strips.tsx`) holds the "Opens in a new tab" note once (`strips-new-tab`, passed down as `newTabId`), the repo strip, the products column and the planets canvas, in that DOM, focus and reading order at every width. From `64em` the card grows to `--container-page-max: 68rem` (the profile block keeps its widths and stays centered) and `.card-strips` is a two-column grid (rows `auto 1fr`, a `1.5rem` column gap): repos left, products right. Each `.strip` section spans both rows with `grid-template-rows: subgrid`, so both headings share one row and both lists one height; the repo list sets it (`.product-grid` has `grid-auto-rows: 1fr`, the product line clamps at 2 lines), and the column bottoms line up within 1 px. The two columns must not make the card taller than the one-column card was (1280x720 641 px, 1366x768 659 px, 1440x900 815 px, 1920x1080 886 px; within 2 px). Below `64em` the strips stack, repos then products, with product tiles 2 per row from `40rem` and 1 per row below.
- Products column (`product-strip.tsx`, `<section aria-labelledby="products-heading" data-products>`): the heading "2 products" (`en.products.headingOne`/`headingOther`) with the repo heading's eyebrow and rule, then `ul.product-grid > li > .repo-tile.product-tile`. A tile shares the repo tiles' glass, `--radius-lg`, hover lift, pointer light, focus ring and stretched link (`a.repo-link` to the product, new tab, `rel="noopener noreferrer"`, `aria-describedby` = the new-tab note plus the line). It holds the logo planet (`2.75rem`, `2.5rem` at `(min-width: 48em) and (max-height: 51.4375em)`), the name, a muted "role · period" line (`productMeta`) in place of chips and one line of text; `--lang` is the product's `tint`, so the hover edge glows in the brand color (hirista orange, Safety Real Time green). No stars, forks or status dot.
- Logo planets: `product-mark.tsx` renders `span.logo-planet[data-logo]` with an `aria-hidden` inline `svg` (a disc `circle`, then a `g[transform]` of `path[data-ink="mark"|"accent"]`) filled from the inline `--logo-disc`, `--logo-mark` and `--logo-accent`. That flat mark is the fallback (no JS, no WebGL, software renderer, Save-Data, context loss, forced colors, print) and the source the canvas reads, so the path data ships once. `RepoPlanetsCanvas` sits in `.card-strips` and uses its parent as the stage; `repo-planets.ts` finds `.repo-planet` and `.logo-planet` nodes and sets `data-planets="gl"` on the stage itself, and `@media screen and (forced-colors: none)` hides `[data-planets="gl"] .logo-planet svg` with a 300 ms fade once the first frame (the night-side pose) is drawn. `createLogoPlanet(node, sphere, renderer, time)` (`src/lib/logo-planet.ts`) draws the paths with `Path2D` into a 256x256 mask (mark ink red, accent ink green, `lighter`; the `<g>` transform applied by hand, as `Path2D` ignores ancestor transforms), uploads it as a `CanvasTexture` (`NoColorSpace`, anisotropy `min(4, max)`, mipmaps) and builds one `ShaderMaterial` per logo: the planet lighting with the mask printed on the front hemisphere only, the logo faintly visible on the night side. A missing color or mask throws, and the whole strip falls back to CSS. Repo and logo planets use the fixed view vector `vec3(0, 0, 1)` (orthographic camera), so a rim does not depend on the tile position. Motion (`src/lib/logo-motion.ts`, pure, tested): a sunrise once per page view from -1.9 rad (the night side) to 0, ease-out cubic, 2.4 s, starting the first time the logo is 60% visible while the canvas runs (one `IntersectionObserver` per logo), and never before the first frame is drawn, so the first frame shows the night side even while `compileAsync` is still pending; then a plus or minus 0.35 rad wobble (period about 9 s, never a full turn). Hover or `:focus-visible` in the tile spins it up like the repo planets (speed x3.4, at most 0.5 rad, the `uHot` glow). A held or paused scene, a freeze or reduced motion snaps an unfinished sunrise to the rest pose with one draw; a hidden tab or an off-screen stage resumes and finishes it. Reduced motion draws one still frame at the rest pose.
