# The dotfiles story (`/work/dotfiles`)

Siblings: `card.md` (the `/work` card), `motion.md`, `sky.md`. One page, not a framework: the next project story is its own thing.

- Copy lives in `src/data/dotfiles-story.ts`. `src/data/dotfiles-stats.ts` holds `storyMeta.updatedAt` and `skillCatalog` (each skill's phase, one line and the skill it hands on to, `next`, in walk order). Move `storyMeta.updatedAt` on every copy or catalog edit: it is the sitemap `lastmod` and the `WebPage` `dateModified`.
- Names, not counts (owner pick 2026-10-22): no line, note, name row or drawing label prints a number. The page names real things instead (tools, rules such as G14, agents, skills, models). The drawing still draws the live counts as shapes (roster ticks, guard ticks, home tiles), never as digits. Every build reads them from GitHub, and the Monday `images.yml` run calls the deploy hook (`CLOUDFLARE_DEPLOY_HOOK`) when it pushes nothing, so the shapes follow the dotfiles repo. By hand: give a new skill an entry in `skillCatalog` (a skill without one still shows as new).
- `copy-rules.ts` checks `line` and `note`, each skill's `what` and `flow`, and the poster facts: 3 to 7 words a line (the two titles excepted), 2 to 4 sentences and 55 words a note, no em dash, no banned word, no question, no exclamation mark, no city, and no number at all (digits or spelled from two up). Strips are real command output and are not checked.
- Facts come from GitHub at build (`dotfiles-facts.ts`): the REST tree and one GraphQL query for three files (hook settings, guard checks, the Cargo manifest). A truncated tree, a missing blob or a count of 0 fails the build, so a moved file shows up at once.
- DOM: `section.story[data-story-root]` holds the rail, `div.story-stage` (posters, `canvas.story-canvas`, `div.story-labels`) and `ol.story-steps > li.story-step[data-step]`. The canvas and labels are `aria-hidden`; each step carries every fact a label shows.
- One pure geometry (`blueprint-geometry.ts`) feeds the WebGL renderer and the build-time SVG posters. Counts reach the browser as `data-story-counts`.
- Client modules import `StepId` from `step-ids.ts`, never `steps.ts`: that pulls zod and the copy into the chunk.
- Page pattern: a steep floor behind the whole page, pure CSS on two fixed pseudo layers, no new element. Both are one plane (`--story-depth` tall, 200vw wide, origin at the bottom edge) tilted by `--story-tilt` (`perspective(180vh) rotateX(68deg)`): the horizon sits near 0.3 of the screen height and the grid fades out before it. `[data-story]::before` is the grid (`--story-grid-minor` every `--story-cell`, `--story-grid-major` every `--story-cell-major`; columns are `--story-col` wide; rows are `--story-row` thick because a thin row shrinks under a pixel and breaks into dashes; owner pick 2026-10-22: thicker and dimmer lines, so the floor reads see-through). Anti-moiré rule: no line may get denser than about 3 px per cell on screen. Minor lines are hidden by a paper gradient layer in plane space, all lines by `--story-plane-fade` (a plane-space mask, also the side fade), and `--story-floor-dim` dims the near middle. `[data-story]::after` is a copy of the grid in `--story-wave-minor` and `--story-wave-major`, only the near 40% of the plane (where the wave shows, so its mask repaint and layer memory stay small; same bottom origin, so its lines sit on the rest lines) (the crest stays under 3x the rest alpha), masked by a diagonal band (`to bottom right`) whose position is the registered `@property --story-wave-at`, animated by `story-wave` (8 s, one wave across the floor from the top left to the bottom right, lights only the grid lines; owner pick 2026-10-22, it replaced a round pulse from the middle). Scroll sway: both layers get `story-sway` (`rotate` about the bottom middle, `animation-timeline: scroll(root)`, inside `@supports`), so the lit lines always sit on the rest lines. Reduced motion and `:root[data-motion-paused]` remove both animations: a still floor, no pulse. The stage and posters are transparent and the canvas clears to alpha 0 (premultiplied blend), so the drawing sits on the same floor with no seam.
- Text shade: owner-approved exception (2026-10-22) to "no boxes or shadows behind text", story page only. Two layers. (1) A frosted backdrop: `.story-body::before` reaches `--story-frost-x` and `--story-frost-y` past the text and carries `backdrop-filter: blur(var(--story-frost))` (4px, plus the `-webkit-` twin; 3.5em by 2.5em past the text, full strength from just inside the text box). Two eased linear masks (`--story-frost-soft` at the half ramp) meet by `mask-composite: intersect`, so it has no edge and no box at any size: the drawing behind the text turns into soft light. No ancestor of `.story-body` may carry `filter`, `opacity` under 1, `mask`, `clip-path`, `mix-blend-mode` or a `will-change` of those: each makes a backdrop root and the blur then sees nothing. Pixel proof: `.audit/story-feel-2026-10-22/blur-probe.ts` (fine detail behind the text drops to about 10% of the unblurred value in Chromium, 5% in WebKit; WebKit `page.screenshot` drops the fixed floor layer, so WebKit is proved by video frames, `blur-webkit-video.ts`). During the `/work` morph the hero frost hides (`:root[data-story-morph]`, the hero body is its own view-transition group and so a backdrop root) and fades in after. (2) The letter glow: a stacked paper `text-shadow` (0.2em, 0.6em, 1.4em with `--story-shade`, 3em with `--story-shade-mid`). The hero morph name drops it during the morph, so both name images keep one shape. The renderer dims lines under the text to `dimTo` 0.35 (was 0.2 before the frost). Do not go back to an opaque box or a dark radial behind the text.
- Renderer: one WebGL2 context (alpha, cleared transparent), two programs, DPR at most 1.5, no three.js. It sizes from the canvas rect. No WebGL2 or a software renderer keeps the poster.
- Dotted decoration: slab tops and the title block carry a plane-space dot grid (`blueprint-dots.ts`: pitch 0.125 plane units, radius 0.8 px, alpha `storyPalette.dot` via `--story-dot`). The face program draws three passes: a depth-only pass (color masked) that keeps the nearest face per pixel, the faint fill with no depth test (fills blend as before), then the dots once with `LEQUAL` and no depth writes, so a lower slab's dots hide under a nearer slab's face and the dot alpha matches the poster. Dots fade out between 4 and 7 CSS px of screen spacing (measured from the screen-to-plane derivatives, so no moiré at any size), dim a little with depth, and dim under step text like the lines (`dimShader` is shared by both programs). The build-time SVG gets one `<pattern>` per plane (affine `patternTransform`, ids carry the poster size) with the same pitch, radius and fades; it has no occlusion (the poster is the spread outro). Slides: `.story-plate` has a dotted border, `.story-wire` a round-cap dotted leader, `.story-eyebrow` a short dotted rule.
- The loop runs only while the stage is in view, the tab is visible and motion is allowed. It sleeps once settled. Step offsets come from a ResizeObserver, never from `innerHeight` per scroll.
- `stillQuery()` (reduced motion or the Motion switch): no loop, one still frame per step. Tilt only on `(hover: hover) and (pointer: fine)`.
- Every width: the stage is a sticky `100svh` sheet behind the steps (`svh`, so the address bar never resizes the canvas). The steps scroll over it, text bottom left, 50ch, no box. A label over the step text fades out, and the renderer dims the lines under it. Labels, plates and the line dim (`uDim[3]`) avoid every step text on screen (the current step and its neighbours), not only the current one: a tall step comes in from below while the previous step is still current. Contrast probe: `.audit/work-cards-2026-10-22/contrast-probe.ts`, worst text at least 4.5:1.
- Phones (under 48em): at most four labels (`phoneLabelLimit`); a leader draws only for a kept label. `frameMatrix` lifts a portrait frame (`tallLift`) so the drawing sits above the text. The step cue is a 2px accent line under the bar (`.story-stage::before`, `--story-progress`); desktop has the rail instead. The rail is a sticky `100svh` box (the stage pulls up under it), so it ends with the story and never covers the footer.
- The share image `public/og-dotfiles.jpg` comes from `scripts/generate-images.ts` (the poster, the word and a "Drawn by" title block with the portrait, name and domain: the brand on every share). It reads the facts, so CI needs `GITHUB_TOKEN`. `images.yml` also runs every Monday, so the counts follow the dotfiles repo.
- Every command strip shows a real command and its real output. A list that no command prints uses `title` instead of `command` (no `$` prompt).
- The strips show inside the drawing as plates (`story-plates.ts`): one `aria-hidden` `.story-plate` per strip in `.story-labels`, cloned from the step's `pre.story-strip`, plus one `svg.story-wire` leader. `buildScene` gives each step a `plate` anchor (`Scene.plate`, a slab corner or the part the step is about), projected like the labels. `plateSpot` puts the plate under the bar; on desktop right of the step text, on phones full width. A plate over the step text fades out. Rows clamp at two lines; phones show the command and four rows.
- While live, the HTML strip stays in the step (region and name) but is visually hidden and loses `tabindex`. The poster path (no WebGL) shows the strip under the note as before. `h2` has no plate: the scene itself draws the ledger rows.
- Text dwell (CSS only, `story.css`): no code ever moves the scroll, except a rail tick or a skip link the visitor clicks. Each `.story-body` has its own view timeline (`--story-text`, insets: the bar plus `--sp-2` on top, the step bottom padding below), so `entry 100%` is its read spot: the text bottom on the bottom padding, or for a text taller than the screen its top under the bar. Within `--story-dwell` (50vh of scroll) of that spot, `@keyframes story-dwell` adds a `translate` that is an odd smooth curve of the distance: about 0.55x scroll speed at the spot, up to about 1.35x on the way out, at most 6.4vh of offset, 0 outside the range. The text never sits below its read spot and only one text moves at a time, so it never overlaps a neighbour. The subject's own transform does not feed its view timeline. Labels, plates and the line dim read `getBoundingClientRect`, which includes the offset. Browsers without `animation-timeline` scroll 1:1. Reduced motion and `:root[data-motion-paused]`: `animation: none`. The old scroll magnet (`story-magnet.ts`) was dropped on 2026-10-22: the owner felt the pull as a fault. Native `scroll-snap` was dropped before it. `magnet` in `math.ts` stays for the Weather range `snapStop`. Rail ticks land on the read spot (`block: "end"` unless the text is taller than three quarters of the screen); steps carry `scroll-margin-block-end` that cancels the page's bottom scroll padding.
- Skills walk (`skills` step, eyebrow H4, after `h3`): every skill of the harness sits on the harness sheet floor along the work loop (`skill-map.ts`: ask, research, design, build, review, ship columns, care as a band in front). The step is half a screen per skill plus one finale screen (`--story-stops` on the `li`, `data-stops` for the mount); `walkOf` ends the walk one screen before the step ends, so the last stop never meets the outro, and the finale shows the finished map. While live its `.story-body` is sticky at the bottom and has no dwell; when it is taller than the room under the bar (200% text), `measure()` sets `data-story-loose` and it is not pinned (the plates carry each skill). Per stop: the path draws to the skill, the slab lifts in the accent tone, and the plate shows that skill (one `[data-plate]` `li` per skill, cloned like a strip; `place(index, ..., sub)`). Charts draw in with the walk: phase gauges (arc = share of the skills in that phase) and bridges for each catalog hand-off (`next`). A slab's height grows with its hand-offs, so hubs stand taller. The plate's last row is the flow ("Hands on to X.", "Takes work from X." or "Works on its own."). A skill missing from the catalog is a dashed outline with "New in the harness." No usage data: the owner's own session stats never ship (the old `skill-usage.json` was removed and scrubbed from git history on 2026-10-22). The rail gets one sub-tick per skill while the step is current. Still mode: one frame per stop (`stillGoal`). The poster path shows the list, the chart text and a build-time SVG of the finished map (`.story-skill-poster`).
- Skill names come from the GitHub tree (`facts.skillNames`, the `claude/skills/ps_*/SKILL.md` paths). A name missing from the data gets phase `care` and the new copy, so a new skill never breaks the build or the walk. The phase and the line of a known skill come from `skillCatalog` in `src/data/dotfiles-stats.ts`.
- Drag (owner pick 2026-10-22, free orbit): `story-orbit.ts` on the stage. A mouse drag turns the drawing a full circle across the stage width and tips it within `orbitPitch`; a touch drag turns only (the stage has `touch-action: pan-y`, so a vertical swipe still scrolls). It stays where it is left; a double click resets it. The orbit adds to the hover tilt and turns the GL grid with the drawing. It works in still mode too (one frame per move, no loop), because it follows the hand and never plays by itself. Cursor `grab`, `grabbing` while `data-story-drag` is set.
- The `/work` morph names live under `html[data-story-morph]` (`story-morph.ts`), because `title-morph.ts` strips inline names.
- Budget: the page's own JS under 35 KB gzipped. Gate: `pnpm audit:site --only story` at 320, 390, 768, 1024, 1440 and 390 with a 200% root font.
