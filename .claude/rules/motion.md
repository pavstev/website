# Motion, dock and privacy

Loads when you touch the pause button, the dock, the privacy note, the head script or the motion helpers. Sibling rules: `card.md`, `globe.md`, `sky.md`.

- Head script: one plain inline `<script>` is the first child of `<head>` in `src/layouts/Base.astro` (`headScript` in `src/lib/motion-pause.ts`, inlined with `set:html`). It runs before first paint. It sets `data-js` on `<html>`, then, inside a `try` so blocked storage only skips them, `data-privacy-ack` and `data-motion-paused` when `localStorage` holds them. Keep it a plain inline script in `<head>`, never a module or a deferred script, so the flags are set before first paint. It runs only on a full load: both layouts load `ClientRouter` (`src/components/page-router.astro`), which swaps pages without running it, and `src/lib/router-flags.ts` copies the live `<html>` `data-*` attributes onto the incoming document before each swap, so the flags survive. The CSP already allows inline scripts. The home to blog sky shot (`sky.md`) is an instant swap under the pause button, reduced motion, for crawlers, Save-Data, a software renderer and without WebGL; pausing or turning on reduced motion mid-shot ends it at once.
- Dock (`page-dock.tsx`, a `<footer class="page-dock">` after `main`): only the privacy note, centered at the bottom. From `(min-width: 48em) and (min-height: 45em)` (768x720 and up, so the 768 to 1023 px band that scrolls is included) the dock is `fixed` and `#main-content` takes the full height and reserves `--privacy-zone` (`padding-bottom: max(var(--safe-y, 2.5rem), calc(var(--privacy-zone) + 1rem))`), so the chip is on screen at load and the © footer clears it at the end of the scroll; below that it sits in the flow after `main` (a sticky chip covered the contact links on short phones, WCAG 2.5.8). Blog pages wrap the dock in `.blog-dock`, which keeps it in the flow at every size, at the page end under the blog footer (see the Blog bullet in `docs/architecture.md`). `:root[data-privacy-ack] .page-dock` and `:root[data-privacy-closed] .page-dock` hide it (outside any media query), so no empty `<footer>` landmark is ever left. Print hides it. The fade-in sits on `.privacy-chip-face`, not on a parent (an animated parent breaks the backdrop blur).
- Privacy note (`privacy-note.tsx`, a `div`, plus the `privacy-ack.tsx` button): a round glass chip, "No cookies, anonymous stats", in the dock. It is a `<button popovertarget>`; the panel is `popover="auto"` (with the topic panels' scroll fade when it scrolls) with the lines from `en.privacy` and an OK button (44 px tall hit band on coarse pointers through `.privacy-ack::after`, the look unchanged). OK stores `privacy-ack` in `localStorage`, closes the panel and sets `data-privacy-closed` on `<html>`: the dock goes at once and `--privacy-zone` drops to `0px` (owner ask 2026-10-12), so the gap under the footer closes; `#main-content` eases its `padding-bottom` over `--duration-slow`, so the card glides instead of jumping. On later visits the head script sets `data-privacy-ack` before paint, which hides the dock and sets `--privacy-zone: 0px`: the no-scroll card is centered without an empty band, the scrolling pages end sooner and `scroll-padding-bottom` drops to `1rem`. The panel is anchored above the chip (`position-area: top`, `justify-self: center`) and keeps at least 16 px from both screen edges down to 195 px wide. Cloudflare Web Analytics is switched on in the Cloudflare dashboard (automatic beacon, cookieless); the CSP allows `static.cloudflareinsights.com` (scripts) and `cloudflareinsights.com` (connect). The note must stay true: no cookies, no ads, no trackers that follow people. Adding anything that sets cookies needs a real opt-in flow first (Decline as easy as Accept).
- Pause motion (WCAG 2.2.2): `motion-toggle.tsx` renders `<header class="motion-item">` (a banner landmark before `main`, so the button is the first Tab stop) with a round glass button: a `2rem` disc (`.motion-glyph`, 1px `--border-strong`, dark glass with a blur, like the contact links) inside a `2.75rem` hit area, holding a pause icon of two bars that morphs into a play triangle when paused (owner 2026-10-13, Q8; two `.motion-bar` spans whose `clip-path` polygons turn from the bars into the two halves of the triangle over `--duration-normal`; `:root[data-motion-paused] .motion-bar` keeps that duration with `!important`, the one deliberate exception to the paused reset, as the item is hidden under OS reduced motion anyway). No text on the button: its `aria-label` follows the state ("Pause motion" / "Play motion", `en.motion.pause` / `play`), so there is no `aria-pressed`. Paused, the disc border turns blue. `variant?: "corner" | "bar"` (default `"corner"`): `"bar"` renders the same button and tip in a `div.motion-item[data-variant="bar"]` with no `<header>` landmark and no absolute position, for a sticky bar. Place (corner): `position: absolute` at `max(0.75rem, env(safe-area-inset-top))` and `max(0.75rem, env(safe-area-inset-right))` from the page's top-right corner, so it scrolls away with the page; `fixed` under the no-scroll gate. It clears the portrait and the name at every size from 160 to 1920 px wide; below `17em` (200% zoom on a phone) `#main-content` gets `3.5rem` more top padding while the button shows (JS on, no reduced motion), so the card starts below it. Place (bar): blog pages render no corner button; `blog-header.astro` puts `<MotionToggle variant="bar" />` in the blog bar's `[data-bar-slot]` (the right end of the sticky bar), so it stays on screen while you read; `src/layouts/BlogLayout.astro` renders none. Its tip opens below the bar, anchored to the right edge. Focus ring on the disc (2px `--primary`, 2px offset); forced colors draw the disc in `ButtonFace` with a `ButtonText` border and the bars in `ButtonText` (`forced-color-adjust: none` on the bars; `Highlight` when paused and for the focus ring), because the sky canvas stays dark under a light high-contrast theme. Its tooltip has the `.contact-tip` look (radius `0.875rem`, so a wrapped tip stays tidy), opens below the button right-aligned with it, shows on hover and `:focus-visible`, stays while hovered, is linked by `aria-describedby` to the line of the current state and dismisses on Escape: "Pause the moving sky" over "Stops the sky, clouds, rays and planets." (`en.motion.tipPause`, `tipPauseDetail`), and "Play the moving sky" over "Starts the sky, clouds, rays and planets again." when paused. Touch has no hover, so a tap (`pointerType` read on `pointerdown`) toggles and sets `data-flash` for 2 s, and the tip shows the new state; for every pointer the tip stays right of the portrait (`max-width: calc(50vw - 7.75rem)`), below `34em` it is a toast at the bottom center above the dock zone, and below `34em` on screens under `28em` tall there is no tip at all (the icon already shows the state), so it never covers the portrait or the name. `.motion-item` is hidden without JS (no `data-js`), under OS reduced motion (where nothing is left to pause) and in print. State: `html[data-motion-paused]` plus `localStorage["motion-paused"] = "1"`, removed on resume; storage errors make it session-only, and a `storage` event makes other tabs follow. `setMotionPaused` sets both, then dispatches `scene:hold` and `motion:pause`; the toggle reads it through `useSyncExternalStore(subscribeMotionPause, isMotionPaused, () => false)`. `scene-hold.ts` owns the attribute name and `isSceneHeld()` is "held or paused", so the globe's `holdScene(false)` on close cannot undo a pause; `motion-pause.ts` imports from `scene-hold.ts`, never the other way (a cycle fails `import-x/no-cycle` and knip). Canvases (sky, repo and logo planets, name tear) stop through `isSceneHeld()` and keep their last frame, and the sky reports `paused`. While held or paused the sky also ignores pointer moves (star parallax, gusts, puffs), so nothing swings or plays on resume; the sky has no click effect (the owner dropped the click ripple on 2026-10-13). DOM loops (`name-glitch`, `cursor`, `contact-links`, `pill-aurora`, `download-ring`, `intro`, `portrait-effects`, `portrait-expand`, `city-globe`) take their reduced-motion path through `stillQuery()`, an object shaped like a `MediaQueryList` that matches reduced motion or the pause and fires `change` for either. `space-background.tsx` and `repo-planets.ts` keep `reducedMotionQuery`. CSS: `@custom-variant still` (reduced motion, or `:root[data-motion-paused] &`) is used only as `@variant still` nested in a rule with one selector and no pseudo-element (a top-level one emits `:scope`, which never matches, and a selector list loses its pseudo-elements). Every other reduced-motion rule, the universal `0.01ms` reset included, has a hand-written `:root[data-motion-paused]` twin right after it; the only rule without one is the `.motion-item` hide, as the button must stay to resume, and the `.motion-bar` paused duration above is the one deliberate exception to the paused reset. The drawers' slide (`card.md`) has a reduced-motion rule and its paused twin. After a CSS change, the built CSS must hold no `:scope` and a paused twin for every other reduced-motion selector.
- `prefers-reduced-motion`: the intro exits early; sky, portrait effects and cursor scripts also follow the setting when it changes at runtime; CSS animations collapse to `0.01ms`. The pause button reuses these paths (see Pause motion). Pointer-following effects (star parallax, cloud wind) run only for `(hover: hover) and (pointer: fine)`; the portrait bead is the one exception, as it also follows a finger after a press and hold.
- Start order: the repo and logo planets start only when a drawer opens (see Drawers in `card.md`) and stop when it closes. The name tear engine starts on idle without waiting for `load` (`scheduleIdle`); on coarse pointers (`isCoarseDevice` in `src/lib/idle.ts`, the inverse of `finePointerQuery`) it goes through `scheduleStaggered`, which waits for `load` and runs on an idle period. The portrait bead builds its engine on the first hover or long press, never at mount.
