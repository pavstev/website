# Motion, dock and privacy

Loads when you touch the pause button, the dock, the privacy note, the head script or the motion helpers. Sibling rules: `card.md`, `globe.md`, `sky.md`.

- Head script: one plain inline `<script>` is the first child of `<head>` in `src/layouts/Base.astro` (`headScript` in `src/lib/motion-pause.ts`, inlined with `set:html`). It runs before first paint. It sets `data-js` on `<html>`, then, inside a `try` so blocked storage only skips them, `data-privacy-ack` and `data-motion-paused` when `localStorage` holds them. Keep it a plain inline script in `<head>`, never a module or a deferred script, so the flags are set before first paint. It runs only on a full load: both layouts load `ClientRouter` (`src/components/page-router.astro`), which swaps pages without running it, and `src/lib/router-flags.ts` copies the live `<html>` `data-*` attributes onto the incoming document before each swap, so the flags survive. The CSP already allows inline scripts. The home to blog sky shot (`sky.md`) is an instant swap under the pause button, reduced motion, for crawlers, Save-Data, a software renderer and without WebGL; pausing or turning on reduced motion mid-shot ends it at once.
- Dock (`page-dock.tsx`, a `<footer class="page-dock">` after `main`): only the privacy note, centered at the bottom. From `(min-width: 48em) and (min-height: 45em)` (768x720 and up, so the 768 to 1023 px band that scrolls is included) the dock is `fixed` and `#main-content` takes the full height and reserves `--privacy-zone` (`padding-bottom: max(var(--safe-y, 2.5rem), calc(var(--privacy-zone) + 1rem))`), so the chip is on screen at load and the © footer clears it at the end of the scroll; below that it sits in the flow after `main` (a sticky chip covered the contact links on short phones, WCAG 2.5.8). Blog pages wrap the dock in `.blog-dock`, which keeps it in the flow at every size, at the page end under the blog footer (see the Blog bullet in `docs/architecture.md`). `:root[data-privacy-ack] .page-dock` and `:root[data-privacy-closed] .page-dock` hide it (outside any media query), so no empty `<footer>` landmark is ever left. Print hides it. The fade-in sits on `.privacy-chip-face`, not on a parent.
- Privacy note (`privacy-note.tsx`, a `div`, plus the `privacy-ack.tsx` button): an interior.dev dark float chip (`.mat-float`, `--ui-radius-lg`, no blur, Geist 12 px weight 500 in `--ui-ink-2`, a 6 px `--ui-moss` dot), "No cookies, anonymous stats", in the dock. It is a `<button popovertarget>`; the panel is `popover="auto"` and the interior popover material (`.mat-pop`, `--ui-radius-pop` 11 px, 1px hairline, 12 px padding, 12.5 px Geist on a 1.625 line in `--ui-ink-2`, the lead line in `--ui-ink`, the mail link in `--ui-accent`, hairline dividers, OK as a `--ui-well` key with `--ui-shadow-cap`; the topic panels' scroll fade ends in `--ui-panel`) with the lines from `en.privacy` and an OK button (44 px tall hit band on coarse pointers through `.privacy-ack::after`, the look unchanged). OK stores `privacy-ack` in `localStorage`, closes the panel and sets `data-privacy-closed` on `<html>`: the dock goes at once and `--privacy-zone` drops to `0px` (owner ask 2026-10-12), so the gap under the footer closes; `#main-content` eases its `padding-bottom` over `--duration-slow`, so the card glides instead of jumping. On later visits the head script sets `data-privacy-ack` before paint, which hides the dock and sets `--privacy-zone: 0px`: the no-scroll card is centered without an empty band, the scrolling pages end sooner and `scroll-padding-bottom` drops to `1rem`. The panel is anchored above the chip and keeps at least 16 px from both screen edges down to 195 px wide: `src/lib/anchored-popovers.ts` places it (`data-anchored="always"`, `data-placement="top"`, flips below the chip if there is no room) and it opens and closes with the shared popover motion (Bio topics in `card.md`); before the script runs, or without it, `position-area: top` and `justify-self: center` place it, and `[data-floating]` turns those off. Cloudflare Web Analytics is switched on in the Cloudflare dashboard (automatic beacon, cookieless); the CSP allows `static.cloudflareinsights.com` (scripts) and `cloudflareinsights.com` (connect). The note must stay true: no cookies, no ads, no trackers that follow people. Adding anything that sets cookies needs a real opt-in flow first (Decline as easy as Accept).
- Pause motion (WCAG 2.2.2): `motion-toggle.tsx` renders `<header class="motion-item">` (a banner landmark before `main`, so the button is the first Tab stop) with a square keycap: a `2.25rem` key with `--ui-radius-key` corners, the 36 px of interior's Icon Morph button (owner pick 2026-10-15: square like the other keys, not round) (`.motion-glyph.keycap`: `--ui-panel`, a 1px `--ui-hairline` border, the icon in `--ui-key-ink`, with a `.keycap-base` that peeks 4 px below it, like the contact links) inside a `2.75rem` hit area, which fills with `--ui-well` on hover and sinks 4 px onto its base while pressed (`:active`, CSS only, on the press spring from `--press-ease`), holding a pause icon of two bars that morphs into a play triangle when paused (owner 2026-10-13, Q8). The icon is the interior Icon Morph (`src/components/ui/icon-morph.tsx`): two SVG paths with matching commands that motion animates from the bars to the two halves of the triangle with a spring. It does not use `useStill()`: the pause itself turns `useStill()` on, so the morph would never play; this is the one deliberate exception to the paused reset, as the item is hidden under OS reduced motion anyway. No text on the button: its `aria-label` follows the state ("Pause motion" / "Play motion", `en.motion.pause` / `play`), so there is no `aria-pressed`. Paused, the disc ring and the play icon turn `--ui-accent`. `variant?: "corner" | "bar"` (default `"corner"`): `"bar"` renders the same button and tip in a `div.motion-item[data-variant="bar"]` with no `<header>` landmark and no absolute position, for a sticky bar. Place (corner): `position: absolute` at `max(0.75rem, env(safe-area-inset-top))` and `max(0.75rem, env(safe-area-inset-right))` from the page's top-right corner, so it scrolls away with the page; `fixed` under the no-scroll gate. It clears the portrait and the name at every size from 160 to 1920 px wide; below `17em` (200% zoom on a phone) `#main-content` gets `3.5rem` more top padding while the button shows (JS on, no reduced motion), so the card starts below it. Place (bar): blog pages render no corner button; `blog-header.astro` puts `<MotionToggle variant="bar" />` in the blog bar's `[data-bar-slot]` (the right end of the sticky bar), so it stays on screen while you read; `src/layouts/BlogLayout.astro` renders none. Its tip opens below the bar, anchored to the right edge. Focus ring on the disc (2px `--primary`, 5px offset, clear of the base); forced colors draw the disc in `ButtonFace` with a `ButtonText` border and the icon in `ButtonText`, and the base in `ButtonText` (`forced-color-adjust: none` on `.motion-icon`; `Highlight` when paused and for the focus ring), because the sky canvas stays dark under a light high-contrast theme. Its tooltip is the interior Tooltip (`src/components/ui/tooltip.tsx`, alone, so no gliding) with the `.tip` look (the interior.dev dark tooltip of the contact tips, 8 px radius, padding `0.25rem 0.5rem` even when it wraps, at most 14rem wide with balanced lines), opens below the button right-aligned with it, shows on hover (after 200 ms) and `:focus-visible`, stays while hovered, is linked by `aria-describedby` while it shows and dismisses on Escape or pointer down: "Pause the moving sky" over "Stops the sky, clouds, rays and planets." (`en.motion.tipPause`, `tipPauseDetail`), and "Play the moving sky" over "Starts the sky, clouds, rays and planets again." when paused. Touch has no hover, so a tap (`pointerType` read on `pointerdown`) toggles and pins the tip open for 2 s (the Tooltip's `pinned` prop; Escape ends it), and the tip shows the new state; for every pointer the tip stays right of the portrait (`max-width: calc(50vw - 7.75rem)`), below `34em` it is a toast at the bottom center above the dock zone, and below `34em` on screens under `28em` tall there is no tip at all (the icon already shows the state), so it never covers the portrait or the name. `.motion-item` is hidden without JS (no `data-js`), under OS reduced motion (where nothing is left to pause) and in print. State: `html[data-motion-paused]` plus `localStorage["motion-paused"] = "1"`, removed on resume; storage errors make it session-only, and a `storage` event makes other tabs follow. `setMotionPaused` sets both, then dispatches `scene:hold` and `motion:pause`; the toggle reads it through `useSyncExternalStore(subscribeMotionPause, isMotionPaused, () => false)`. `scene-hold.ts` owns the attribute name and `isSceneHeld()` is "held or paused", so the globe's `holdScene(false)` on close cannot undo a pause; `motion-pause.ts` imports from `scene-hold.ts`, never the other way (a cycle fails `import-x/no-cycle` and knip). Canvases (sky, repo and logo planets, name tear) stop through `isSceneHeld()` and keep their last frame, and the sky reports `paused`. While held or paused the sky also ignores pointer moves (star parallax, gusts, puffs), so nothing swings or plays on resume; the sky has no click effect (the owner dropped the click ripple on 2026-10-13). DOM loops (`name-glitch`, `cursor`, `contact-links`, `intro`, `portrait-effects`, `portrait-expand`, `city-globe`) take their reduced-motion path through `stillQuery()`, an object shaped like a `MediaQueryList` that matches reduced motion or the pause and fires `change` for either. React parts take the same through `useStill()` (`src/lib/use-still.ts`): the tooltips, the PDF button's faces and the drawers skip their springs and fades when it is true. `space-background.tsx` and `repo-planets.ts` keep `reducedMotionQuery`. CSS: `@custom-variant still` (reduced motion, or `:root[data-motion-paused] &`) is used only as `@variant still` nested in a rule with one selector and no pseudo-element (a top-level one emits `:scope`, which never matches, and a selector list loses its pseudo-elements). Every other reduced-motion rule, the universal `0.01ms` reset included, has a hand-written `:root[data-motion-paused]` twin right after it; the only rule without one is the `.motion-item` hide, as the button must stay to resume, and the icon morph above is the one deliberate exception to the paused reset. The press tilt (`card.md`) has a reduced-motion rule and its paused twin; the resume tip's `.resume-line` draw uses `@variant still`. The drawers' slide runs in `motion` and stops through `useStill()` (Drawers in `card.md`), so it has no CSS rule and no paused twin. After a CSS change, the built CSS must hold no `:scope` and a paused twin for every other reduced-motion selector.
- `prefers-reduced-motion`: the intro exits early; sky, portrait effects and cursor scripts also follow the setting when it changes at runtime; CSS animations collapse to `0.01ms`. The pause button reuses these paths (see Pause motion). Pointer-following effects (star parallax, cloud wind) run only for `(hover: hover) and (pointer: fine)`; the portrait bead is the one exception, as it also follows a finger after a press and hold.
- Start order: the repo and logo planets start only when a drawer opens (see Drawers in `card.md`) and stop when it closes. The name tear engine starts on idle without waiting for `load` (`scheduleIdle`); on coarse pointers (`isCoarseDevice` in `src/lib/idle.ts`, the inverse of `finePointerQuery`) it goes through `scheduleStaggered`, which waits for `load` and runs on an idle period. The portrait bead builds its engine on the first hover or long press, never at mount.
