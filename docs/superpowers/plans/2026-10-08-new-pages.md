# New Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a CV data feed, an ask-me AI with chat and MCP routes, project pages built from READMEs, a lab page, a colophon and a now page to stevanpavlovic.com, with a link row on the card.

**Architecture:** The Next.js static export stays the only renderer; new pages are server components built at `next build` from `personal.ts`, `i18n.ts`, the GitHub API and a new CV feed served by the jobsearch app. One Cloudflare Worker in `worker/` runs only for `/api/*` and `/mcp*` (`run_worker_first`); every other path stays a free static asset. The Worker reads its facts from the site's own `/cv.json` and `/llms.txt` through the assets binding.

**Tech Stack:** Next.js 16 App Router (`output: "export"`), React 19, Tailwind v4, zod 4, three.js, Cloudflare Workers with static assets, Workers AI, Turnstile, Workers Rate Limiting, `@modelcontextprotocol/sdk` 1.32, `sanitize-html` 2.18, `cvexp` 2.1 (types only), Node 24 test runner.

**Spec:** `docs/superpowers/specs/2026-10-08-new-pages-spec.md`

> Tasks 1 and 2 (the CV loader and `resume.pdf`) are superseded by `docs/superpowers/plans/2026-10-08-hirista-integration.md`: the feed is read once per build by `scripts/cv-fetch.ts`, `getCv()` reads `.cv/cv.json`, and `resume.pdf` is rendered from the feed with `@react-pdf/renderer`. Task 9 (the Ask panel) is done.

## Global Constraints

- Read the relevant guide in `node_modules/next/dist/docs/01-app/` before writing Next code; `01-app/02-guides/static-exports.md` rules: route handlers need `export const dynamic = "force-static"`, dynamic routes need `generateStaticParams` and `export const dynamicParams = false`.
- No comments, JSDoc, TODO/FIXME/XXX/HACK in source. No `any`, no `!`, no `eslint-disable`. No hardcoded hex or hsl outside `globals.css` and `src/lib/theme.ts`. Every UI string lives in `src/lib/i18n.ts`. Tailwind v4 paren syntax (`bg-(--surface)`).
- TypeScript strict, explicit return types on exports, `import { type Foo }`, kebab-case files, PascalCase components, one component per file in `src/components/`. `process.env` is read with bracket access (`process.env["NAME"]`).
- `package.json` keeps its eight scripts; only the `check` script's contents change. New dependencies go through `pnpm add`; `pnpm-workspace.yaml` policies stay as they are.
- `pnpm check` is the gate and must change no tracked file. husky runs it before every commit (about two minutes, it runs `next build`). CI needs the same secrets the build needs.
- Never edit `dist/`. Never deploy by hand. Push to `main` only when asked. Conventional Commits, no co-author trailer.
- The working tree already holds uncommitted changes from another session (portrait bead, repo tags). Do this work in a worktree (superpowers:using-git-worktrees) branched from `main`; never commit those files.
- Every inner page exports `metadata` with `title` as `{page} · {personalData.name}`, a `description`, `alternates.canonical` and the shared Open Graph image, following `src/app/page.tsx`.
- The build fails on purpose when any external source answers with a non-200 status or invalid data, as `github.ts` does today.
- Phase A needs the jobsearch endpoint from spec Appendix A to exist and the secrets `CV_FEED_URL` and `CV_FEED_TOKEN` set in `.env.local` (local), in the Cloudflare build variables and in the GitHub Actions secrets (also under Dependabot secrets, or Dependabot PRs fail `pnpm check`).

## Review Focus

- A feed answer with a non-empty `basics.phone`: the site must blank it before anything reads it (Task 1).
- A `/api/ask` body with an empty question or more than 500 characters: a 400 with an error code, no AI call, no Turnstile call (Task 7).
- Turnstile verification that throws or returns `success: false`: a 403 and no AI call (Task 7).
- A README with a `script` tag, an `onerror` attribute or a `javascript:` link: all removed, the rest kept (Task 11).
- `now.md` with a malformed first line: the build fails with a message naming the file (Task 13).
