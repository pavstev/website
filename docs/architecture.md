# Architecture

The long Tech Stack notes, moved out of `CLAUDE.md` so they do not load on every turn. Read the bullet for the area you change.

## Tech Stack

- **Framework:** Astro 7, `output: "static"`, `build.format: "file"`, prerendered to `dist/` (`astro.config.mjs`; React 19 islands through `@astrojs/react`; Tailwind v4 through `@tailwindcss/vite`). `build.format: "file"` writes `/blog` as `dist/blog.html` and `/blog/<slug>` as `dist/blog/<slug>.html`; Cloudflare serves them without the `.html` suffix. Routes: `/` (`src/pages/index.astro`, layout `src/layouts/Base.astro`), 404 (`src/pages/404.astro` → `dist/404.html`, `noindex`), `/sitemap.xml` (`src/pages/sitemap.xml.ts`, with image entries; `lastmod` is the CV feed's `updatedAt`, the time the résumé was last saved, never the build time), `/robots.txt`, `/manifest.webmanifest` (`src/pages/manifest.webmanifest.ts`), `/llms.txt` (`src/pages/llms.txt.ts`), `/cv.json` (`src/pages/cv.json.ts`), `/resume.pdf` (`src/pages/resume.pdf.ts`), and the blog: `/blog`, `/blog/<slug>`, `/blog/feed.xml`, `/blog/feed.json` and `/blog/<slug>.md` (see **Blog** below; the sitemap's blog entries use the post dates, not the CV feed's). The home page, `/sitemap.xml`, `/llms.txt`, `/cv.json` and `/resume.pdf` are built from `personal.ts`, `products.ts`, `i18n.ts`, the build-time repo list and the CV feed. The home page stays one card; the only other pages are the blog and the 404.
- **Prefetch and Cloudflare Speed Brain:** `prefetch: false` in `astro.config.mjs` turns Astro's own prefetch off, and `src/lib/link-prefetch.ts` (started from `page-router.astro`, one set of delegated listeners for the whole session) does it instead. Reason, measured 2026-10-15: Astro prefetches with `<link rel=prefetch>`, and Chrome sends `Sec-Purpose: prefetch` for it. Speed Brain is on by default on the Free plan, and it answers that header with `503` and `cf-speculation-refused: prefetch refused: disabled for worker requests`, for every path, because the site is served by a Worker (static assets). The page still worked, but the prefetch never landed and the console showed "Failed to load resource: 503". Speed Brain cannot work for this site: its docs say it skips pages served through a Worker, and there is no per-path off switch (only the zone toggle in Speed, Settings, Content Optimization). A `Sec-Purpose: prefetch;prerender` request is served (200), but `ClientRouter` intercepts the click and fetches, so a prerender is never used and would run the sky for nothing. `link-prefetch.ts` warms the page with a plain low-priority `fetch()` (no `Sec-Purpose`, so the edge answers 200 from cache) on hover (80 ms delay), focus, touch and mouse down, for same-origin links without a file extension, skipping the current page, `target`, `download`, `data-astro-prefetch="false"` and Save-Data. `ClientRouter` then reuses the cached copy: the HTML stays `max-age=0, must-revalidate` with an ETag, so a later fetch is a cheap revalidation and never serves stale HTML after a deploy. A longer `max-age` gained nothing (282 against 294 ms, 5 runs) and was rejected. Home to Blog click to paint, Chrome, 4x CPU and slow 4G, median of 5: 399 ms without a prefetch, 280 ms with the `fetch()` prefetch, live. Speed Brain's own mouse-down speculation got a `503` on every click (a failed request in the Network tab, no console error) until the owner switched Speed Brain off. Checked 2026-10-15: nothing in the repo could remove it, and nothing can make Speed Brain work here. (1) The Worker is the blocker, not the cache: every path answers `disabled for worker requests`, pages that show `cf-cache-status: HIT` included, and `/cdn-cgi/speculation` answers `not eligible`; any `Sec-Purpose: prefetch` request gets the `503` while the zone toggle is on, so a Cache Rule does not help and an own `Speculation-Rules` header in `public/_headers` (Speed Brain does not replace one) could only ask for nothing. (2) Chrome keeps a speculation prefetch for browser navigations only, never for single page app style fetches (Chrome for Developers, "Guide to implementing speculation rules"), so even a host where Speed Brain works would not feed `ClientRouter`; `link-prefetch.ts` is the right tool, and moving to Pages would gain nothing. (3) Switching the rules off does not make a click faster: 22 paired live runs (Chrome, 4x CPU, slow 4G, desktop, Home to Blog click until the blog title is on screen, order alternated): rules on, median 659 ms with a `503` on every click; the rules file replaced by an empty one, median 690 ms; paired difference -43 ms, off faster in 8 of 22. The owner switched the toggle off on 2026-10-15 (account `Pavlovicmstevan@gmail.com's Account`, zone `stevanpavlovic.com`, Speed, Settings, Content Optimization, Speed Brain): the `Speculation-Rules` header is gone, `Sec-Purpose: prefetch` answers `200`, and 14 live real-click runs show no `503`, no console error and a median of 627 ms (same script). Keep `link-prefetch.ts`. With Speed Brain off, Astro's own `<link rel=prefetch>` gets a `200` too, and it tied with `link-prefetch.ts` (2026-10-15: two local `wrangler dev` builds, one with `prefetch: false` plus `link-prefetch.ts`, one with Astro's default, Chrome, 4x CPU, slow 4G, Home to Blog click until the blog title is on screen, 14 paired runs per hover pause, medians): 300 ms hover 386 against 401 ms, 120 ms hover 416 against 416 ms; with no hover pause Astro's own made no prefetch before the click and was 28 ms faster (560 against 592 ms), a case no real pointer produces. The plain `fetch()` stays because it keeps working if Speed Brain is ever switched back on, when the `503` would hit Astro's `<link rel=prefetch>` again. `/cdn-cgi/speculation` still answered `200` an hour later (a cached copy, nothing points to it). Switching the toggle back on brings the `503` back. Sources and the curl matrix: `~/.claude/research/2026-10-15-astro-optimizations/speed-brain-workers-static-assets.md`.
- **Dev:** `devToolbar: { enabled: false }` in `astro.config.mjs`, so `astro dev` shows no Astro toolbar. `pnpm dev` runs the CV fetch and the blog prebuild with drafts, then `astro dev --port 4321`.
- **UI:** Tailwind v4 (`@theme inline` + `@utility`, via `@tailwindcss/vite`). `globals.css` starts with `@import "tailwindcss" source(none)` and `@source "../"`, so Tailwind scans only `src/` and never `.agents/`, `dist/` or old worktrees. `postcss.config.mjs` (plain ESM, not run through Node's type stripping, so it stays `.mjs`) holds only `scripts/postcss-color-mix.mjs`, which Vite runs on the CSS after the Tailwind plugin has produced it: Tailwind puts each `color-mix()` rule in a `@supports (color: color-mix(in lab, red, red))` block after a fallback rule; the plugin drops the fallback declarations and unwraps the block, so every browser gets the `color-mix()` value and a browser without `color-mix()` (Chrome before 111, Safari before 16.2) loses those colors. ESLint ignores the `.mjs` config files (the typed rules need type information they cannot give). Astro components render to HTML at build time and ship no JavaScript; only React islands (hydrated with a `client:` directive) run in the browser: the sky (`space-background.tsx`), the PDF button, the portrait dialog, the planets (`repo-planets-canvas.tsx` → `src/lib/repo-planets.ts`, one raw WebGL2 canvas that draws the repo planets and the logo planets from `src/lib/logo-planet.ts` and `src/lib/logo-motion.ts`, with the matrices, sphere and ring geometry, color conversion and program helpers in `src/lib/planet-gl.ts`; no three.js), the pause button (`motion-toggle.tsx`), the privacy OK button (`privacy-ack.tsx`), the Vienna globe launcher (`city-globe-launcher.tsx`, which imports `city-globe-stage.tsx` → `src/lib/city-globe.ts` only on click) and `effects-init.tsx`. `astro.config.mjs` sets `build.inlineStylesheets: "always"`: each page's stylesheet is inlined into its HTML. The CSS is split per route: `src/styles/globals.css` is the shared sheet (tokens, `@theme`, `@utility`, fonts, base, the sky, the materials, keycaps, tips, drawers, popovers, dock, privacy chip, pause button); `card.css` and `blog.css` hold the rules only the card or only the blog can match, and each starts with `@import "./globals.css"` so Tailwind compiles one sheet per page and the rule order inside it stays the order of the files. Each page imports exactly one entry: `index.astro` imports `card.css`, `BlogLayout.astro` imports `blog.css`, `404.astro` imports `globals.css`, and `Base.astro` imports none. Never import `globals.css` next to a page sheet: Astro orders separate CSS modules by import depth, not by the order of the `import` lines (a first try put the page sheet before the shared one and broke the layer order). A new rule goes to `card.css` or `blog.css` only when every class in its selector is used by that one route (a `.a, .b` list may be split when the parts differ), and stays in `globals.css` when both routes use a class; keep a card or blog rule in `globals.css` when a shared rule of equal specificity that comes later in the file sets the same property on the same element, as moving it would flip the winner. The split took the home HTML from 184 KB to 155 KB, a post from 195 KB to 157 KB and `/blog` from 139 KB to 101 KB (`CV_SNAPSHOT=1 pnpm build`, 2026-10-15). Every page still carries all the Tailwind utilities, because one `@source "../"` scans the whole of `src/` (about 10 KB; splitting that per route is the next cut). `@source not` leaves out tests and `src/profile`, so stray words in them make no utilities. The inlining cut the first text paint from 580 to 330 ms and the first sky draw from 1.81 to 1.56 s on the real throttled probe (`~/powertools/scripts/first-paint-ab.mjs`, 4x CPU, slow 4G, HTTP/2, 2026-10-14). The small `island-style-to-css` integration in the same file removes the invalid `<style>astro-island,...` that Astro's island runtime writes into the body (the audit's html check fails on it) and the same rule lives in `globals.css`. A `modulepreload` list for the sky islands was tried and gave nothing once the CSS was inline (25 ms), so it is not there.

The profile header SVG embeds Inter and Geist. `@font-face` sits at the top of `globals.css`. Metric-matched `local()` fallback faces (`Inter Fallback` on Arial in four weight bands, `Geist Fallback` on Arial Bold, `Geist Mono Fallback` on Courier New, each with `size-adjust` and `ascent-override`, `descent-override`, `line-gap-override`, measured against the real fonts on 2026-10-12) sit right after each font in the stacks, so the swap moves nothing (mobile CLS 0.14 to 0.0007 on Lighthouse with devtools throttling); re-measure them when a font file changes. - **Icons:** `<Icon>` (`src/components/icon.tsx`) renders inline SVG from `src/lib/icon-data.ts`. Sets in use: `circle-flags`, `lucide`, `simple-icons`. A new `set:name` needs `pnpm icons` (run `pnpm add -D @iconify-json/<set>` for each set first, then remove them again).
- **GitHub data:** `src/lib/github.ts` runs at build time. `getRepos` picks the repos and adds every language at 3% or more with its GitHub Linguist color (one GraphQL `repository.languages` query per repo; colors are validated as `#rrggbb` and dropped otherwise). `getContact` reads the public email and the LinkedIn social account from the GitHub profile; `personal.ts` holds neither. `GITHUB_TOKEN` is **required**: GitHub shows a profile email only to authenticated requests. Set it as a Cloudflare build variable. Locally, when it is unset, `github.ts` asks `gh auth token` at run time, so `pnpm dev`, `pnpm build` and the pre-commit hook work without a token file (nothing is written to disk). Any non-200 answer, a missing email or a missing LinkedIn fails the build on purpose. `getProject(login, repo)` (built for project pages, no page uses it yet) returns the default branch, the README rendered by GitHub's `/markdown` endpoint (GFM, repo context) and the last published releases (`per_page=5`, drafts and prereleases dropped, assets kept). `src/lib/readme-html.ts` (`sanitizeReadme`, `sanitize-html`) cleans that HTML: resolves relative links (GitHub blob URLs) and images (raw.githubusercontent.com) against the repo and branch, rejects `..` paths, keeps only http(s) and mailto, opens web links with `noopener noreferrer`, keeps images only from GitHub image hosts, drops badges (shields.io, badge.fury.io), the first `h1`, landmark tags, non-checkbox inputs and links left empty, and keeps links around nested images. Both are covered only by tests so far.
- **CV feed:** `scripts/cv-fetch.ts` runs before `astro build` (`pnpm build`, `pnpm dev` and `pnpm check` all start with it; `pnpm dev` fetches once at start) and asks the jobsearch app (hirista) for `GET {CV_FEED_URL}/api/public/cv` with `Authorization: Bearer {CV_FEED_TOKEN}`, a 20 s timeout and `redirect: "error"`. `CV_FEED_URL` is the origin `https://hirista.app` (the old `js.stevanpavlovic.com` host was removed on 2026-10-12); a URL that is not https fails before any request, except `http:` on `127.0.0.1`, `localhost` and `[::1]` for tests. The script writes the parsed résumé, with `basics.phone` blanked (`stripPrivate`), to the gitignored `.cv/cv.json` and the source (`feed` or `live`) to `.cv/source`; `getCv()` in `src/lib/cv.ts` only reads that file (once per process), so every page, route and the PDF show one version. **Fallback:** only a 20 s timeout, a network error or a 5xx makes the script use the live `https://stevanpavlovic.com/cv.json` (source `live`, a warning in the log). A 404 (the feed answers 404 with an empty body to every refusal: no or wrong token, wrong method, no résumé saved), any other non-200, a redirect, a missing or non-https variable, bad JSON or a schema failure fails the build and never falls back. **Guard:** `scripts/cv-guard.ts` runs after `astro build` and fails the build when the feed's `updatedAt` is newer than the built data (a résumé saved during the build; a newer build is on its way). It is skipped after a `live` fallback or when the feed does not answer. Both scripts load `.env.local` when it exists; `process.env` wins. `cvSchema` mirrors jobsearch's `resumeDataSchema` (`src/cvexp/types.ts` there): `basics`, `summary`, `experience`, `education`, `skills`, `languages`, `projects` (http(s) links only), every field defaulted, plus `updatedAt` (ISO); there is no `cvexp` dependency, as the npm package lacks `projects`. `src/lib/cv-feed.fixture.json` is a byte copy of hirista's `fixtures/cv-feed.json` and `src/lib/cv-contract.test.ts` parses it with `cvSchema`; `.prettierignore` keeps it byte-exact. Change a feed shape in both repos in the same session. Both variables are **required**: Cloudflare build variables, GitHub Actions secrets (`ci.yml`) and Dependabot secrets, locally `~/work/website/.env.local` (gitignored, holds `CV_FEED_URL` and `CV_FEED_TOKEN`). Never print the token; no error message holds it or the URL. Saving a résumé in hirista fires this site's Workers Builds deploy hook. The integration contract and the secrets matrix live in the hirista repo's `DEPLOYMENT.md`, section "Integration contract: hirista.app ⇄ stevanpavlovic.com" (a private repo, so no link). `src/pages/cv.json.ts` serves the result as `/cv.json`; `src/lib/cv-llms.ts` adds Experience, Skills, Education and, when there are any, the résumé's projects to `llms.txt`.

The images are deterministic script output, not AI output: one shader frame from fixed uniforms (no clock, no random), and the PNG holds only `IHDR`, `IDAT` and `IEND` (no metadata or content credentials). The script renders each image twice and fails when the bytes differ; runs on the same platform give identical bytes, while a Mac and the Linux runner differ by at most 6 of 255 in about 0.4% of the channels, so only CI writes the committed files. - **Worker:** `worker/index.ts` is `main` in `wrangler.jsonc` (`nodejs_compat`). `assets.run_worker_first` is `["/mcp", "/mcp/*"]`, so only those paths reach it; every other path is served straight from `dist`. It routes `/mcp` and `/mcp/*` to `mcp.ts` and passes anything else to `env.ASSETS`. There is no Ask panel and no `/api` route: the owner removed them, with their human check and AI binding, on 2026-10-08; do not add either back without a new decision. Bindings: `MCP_LIMITER` (rate limit, 20 per 60 s, keyed by `CF-Connecting-IP`; namespace `2001`; a namespace id is any integer you pick, unique per account, and needs no dashboard step) and `ASSETS`. `worker-configuration.d.ts` is generated by `CLOUDFLARE_LOAD_DEV_VARS_FROM_DOT_ENV=false pnpm exec wrangler types` (rerun after any binding change; without the variable wrangler copies the names in `.env.local` into the file), committed, and excluded from Prettier, ESLint and the root `tsconfig.json`; `worker/tsconfig.json` extends the root one and includes it. Errors are JSON `{ "error": code }` with `Cache-Control: no-store`. Every `/mcp` answer carries `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy` and `Permissions-Policy` (`withSecurityHeaders` in `worker/http.ts`, the same values as the `/*` rule in `public/_headers`; no CSP, as the bodies are JSON or an event stream).
